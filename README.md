# Agent Zero — Agentic Legacy Migration Platform

EXL × UCD Data & AI Hackathon 2026 · **Challenge 03: Agentic data platform modernisation**

Team: Aditya Mahendru, Devesh Shetty, Pritish Salian, Mohammed Shirhaan

## Problem

A UK & Ireland insurer runs finance, actuarial and claims reporting on ~1,200 legacy
ETL jobs (T-SQL) and 400+ SAS programs. Logic is undocumented, lineage is unknown,
and every migrated pipeline must reconcile exactly with legacy outputs.

## What this repo builds (scoped for a 5-hour hackathon build)

A small, honest, end-to-end slice of the full migration platform:

1. **Synthetic insurer data** — policies, claims, premiums generated by a seeded
   Python script (`data/generate_synthetic_data.py`). No real/personal data anywhere.
2. **10 legacy jobs** (`legacy/`) — mostly T-SQL, 2–3 SAS programs, written to carry
   realistic legacy quirks (multi-way joins, `CASE` logic, date handling, aggregations,
   SAS `DATA` steps / `PROC SQL` / BY-group processing).
3. **Agents** (`agents/`), each a `claude -p` headless call with a structured prompt
   and schema-checked output:
   - **Discovery/lineage agent** — parses each legacy job, produces a column-level
     lineage graph and a migration wave plan.
   - **Translation agent** — turns each legacy job into a PySpark job (`pyspark_jobs/`).
   - **Test-generation agent** — writes pytest unit tests for each PySpark job.
4. **Reconciliation engine** (`reconciliation/`) — runs the legacy job and the migrated
   PySpark job on the same synthetic input, diffs row counts, column totals and
   record-level values, and emits a pass/fail report per job.
5. **Human review gate** — every agent-generated change lands in a GitLab merge
   request and is reviewed (by Aditya + the Claude Reviewer CI bot) before being
   counted as "done."

## Default choices made (not asked, flagged here for the record)

- **LLM for all agents:** Claude Code headless (`claude -p <prompt>`), using
  Aditya's existing Claude Code subscription rather than a separate Anthropic API
  key. No `ANTHROPIC_API_KEY` is required to run the agents themselves (CI's
  `claude-review` job uses its own separate credential, already configured at the
  group level).
- **T-SQL legacy baseline:** run against SQL Server in a Docker container
  (`docker/sqlserver/`, `mcr.microsoft.com/mssql/server` under amd64 emulation on
  Apple Silicon) if it comes up within its time budget; otherwise the T-SQL baseline
  falls back to an independent Python/pandas reference implementation of the same
  job, clearly labelled as such in the reconciliation report.
- **SAS legacy baseline:** SAS cannot run in this environment. Every SAS baseline
  is produced by an independent Python/pandas reference implementation of the SAS
  program's documented logic, **not** by executing the original SAS code. This is
  stated explicitly in the reconciliation report for every SAS-derived job and in
  the Responsible AI note — reconciliation against a SAS job is reconciliation
  against a verified-equivalent reference, not the legacy engine itself.
- **Spark runtime:** local PySpark (no Databricks/cluster). Requires a JRE —
  `brew install openjdk@17` if missing locally; the CI `test` job installs
  `default-jre-headless` (whichever JRE the pinned `python:3.12-slim` image's
  Debian release resolves that to) before running pytest.
- **Scheduling/Operate phase:** out of scope for tonight beyond a short design note
  in the architecture doc — no live scheduler is built.

## Repository layout

```
data/              synthetic data generator + generated CSV/Parquet fixtures
legacy/            10 legacy job sources (T-SQL .sql, SAS .sas) + their baselines
agents/            discovery, translation, test-gen agent scripts (claude -p wrappers)
pyspark_jobs/      agent-generated PySpark migrations (one per legacy job)
tests/             agent-generated + hand-written pytest tests
reconciliation/    reconciliation engine + per-job pass/fail reports
docs/              solution deck, architecture diagram, Responsible AI note
docker/sqlserver/  optional local SQL Server container for the T-SQL baseline
```

## Setup

```bash
git clone http://127.0.0.1:8929/workspace/exl-ucd-hackathon-2026.git
cd exl-ucd-hackathon-2026
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
pre-commit install
```

PySpark needs a JRE on `PATH`/`JAVA_HOME`:

```bash
brew install openjdk@17   # if `java -version` fails
```

Generate synthetic data, then run everything:

```bash
python data/generate_synthetic_data.py
python -m legacy.baselines.generate_baselines   # legacy baseline outputs -- see legacy/baselines/MANIFEST.md
pytest
python reconciliation/run_all.py   # produces reconciliation/report.md
```

## AI tools used (declared per hackathon rules)

- **Claude Code** (headless, `claude -p`) — powers the discovery/lineage,
  translation and test-generation agents, and reviews every merge request via the
  `claude-review` CI job.
- No other AI/ML model or service is used anywhere in this repo.
